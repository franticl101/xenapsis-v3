# Xenapsis

Free personality and psychometric assessments. No email, no account, no paywall —
every result renders on screen the moment the last question is answered, and
scoring happens in the visitor's browser.

Built with [Astro](https://astro.build) as a fully static site. 51 pages,
zero client-side framework, ~2KB of JavaScript total.

```bash
npm install
npm run dev          # local dev server
npm run verify       # unit tests → build + SEO audit → e2e → vitals
```

---

## Why this repository is shaped the way it is

This site was built against an SEO audit of a comparable, much older personality
testing site. Its findings were not exotic — a homepage whose `<title>` was the
single word "Home", pages shipping with no meta description, protocol-relative
canonicals, no structured data anywhere, a sitemap returning 404, and images with
no alt text.

What matters about that list is that none of it was a hard problem. Every item
was something a competent team knew better than to do, and shipped anyway,
because **nothing in the pipeline objected.** Fixing those once would leave the
same gap open for whatever ships next quarter.

So each finding is encoded as a build-time invariant instead:

| Finding in the reference audit | How it is prevented here |
|---|---|
| Homepage `<title>` was "Home" | `assertTitle` throws during `astro build` on a generic, missing, short or truncating title. `npm run build` exits 1. |
| Missing meta descriptions | `description` is a required prop on `BaseLayout` and is length-validated at render time. |
| Protocol-relative canonical | Every URL derives from one origin constant via `abs()`, which always returns absolute `https://`. The audit re-checks each canonical on disk. |
| No structured data sitewide | `graph()` emits `Organization` + `WebSite` on every page, with `Quiz`, `FAQPage`, `Article`, `BreadcrumbList` and `ItemList` merged per page. The audit fails any page without valid JSON-LD. |
| Sitemap 404, unreferenced in robots.txt | Sitemap generated by `@astrojs/sitemap`; `robots.txt` is generated from the same origin constant so its `Sitemap:` line cannot drift. Both are verified post-build. |
| Images with no alt text | The audit fails any `<img>` without `alt`, and also without `width`/`height`, since missing dimensions cause layout shift. |
| Page `<h1>` reused the site tagline | The audit fails pages with zero or multiple `<h1>`, or an `<h1>` that looks like a tagline. |
| `<h2>` tags were login UI chrome | The audit fails `<h2>` elements reading "Welcome", "Reset Password", "Create Account" and similar. |
| Two URLs serving near-identical content | Duplicate `<title>` or `<meta description>` across any two indexable pages fails the audit. Career pages carry a [separate content layer](src/data/careers.ts) so they cannot collapse into restated type profiles. |
| Stale content, 8 months since last post | `dateModified` is emitted on every article, and guide frontmatter requires explicit `published`/`updated` dates. |
| Core Web Vitals "not measured" | `npm run vitals` measures LCP, CLS, transfer and request count against budgets in CI. |

Run `npm run audit` against any build to see the current state.

## Architecture

```
src/
  lib/
    site.ts        Origin constant; every absolute URL derives from it
    seo.ts         Build-time title/description guards — these throw
    schema.ts      JSON-LD builders, composed into one @graph per page
    scoring.ts     Pure scoring functions (no DOM) — shared by browser and tests
    nav.ts         Navigation declared once, consumed by header and footer
    dates.ts       Freshness signals
    text.ts        Word count and reading time from raw Markdown
  data/
    types.ts       16 type profiles
    careers.ts     Career content, deliberately distinct from type profiles
    tests.ts       4 assessments, 132 items
  layouts/
    BaseLayout.astro   Requires title + description; emits canonical, OG, JSON-LD
  components/
    TestRunner.astro   The assessment runtime
  content/guides/      Markdown guides, frontmatter validated by Zod
scripts/
  seo-audit.mjs        Post-build site-wide audit (exits 1 on error)
  generate-og.mjs      Renders the Open Graph image from brand tokens
  measure-vitals.mjs   Core Web Vitals against budgets
tests/
  scoring.test.ts      13 unit tests
  e2e/assessment.mjs   7 browser checks against the built output
```

### Instrument design

All 132 items are **keying-balanced**: every scale carries equal numbers of
forward- and reverse-worded statements. A respondent who selects "strongly
agree" for all 48 questions on the type test scores exactly 50% on every
dimension — an honest "no preference detected" rather than the flattering
extreme an unbalanced instrument would return. This is covered by a unit test so
it cannot silently regress if items are edited.

Results lead with **preference strength** rather than a bare four-letter code,
because a type where one dimension scored 3% is a materially different result
from one where every dimension scored 80%.

### Performance

Measured locally, gzipped, against the built output:

| Page | LCP | CLS | Transfer | Requests |
|---|---|---|---|---|
| Homepage | 108ms | 0 | 6.9KB | 3 |
| 48-question test | 116ms | 0 | 15.7KB | 5 |
| Type profile | 116ms | 0 | 8.4KB | 3 |
| Guide article | 68ms | 0 | 8.4KB | 3 |

Reproduce with `npm run vitals`.

Choices behind those numbers:

- **No client framework.** The only JavaScript is the ~2KB assessment runtime.
- **System fonts only**, so there is no render-blocking font request and no
  layout shift from a late swap.
- **Test config travels as a JSON island**, not inlined into the script, so the
  behaviour bundle is byte-identical across all four test pages and the second
  test a visitor takes reuses the cache.
- **One delegated listener** serves all 132 inputs. Progress updates touch two
  nodes rather than re-rendering.
- **No scroll or resize listeners exist**, so there is nothing to throttle.
- **Inline SVG for all iconography** — no image requests, no CLS, no alt-text gap.

### Accessibility

- Each question is a `role="radiogroup"` labelled by its statement, using native
  `<input type="radio">` so arrow-key navigation and roving tabindex come for
  free. `<fieldset>`/`<legend>` was the first approach and was dropped: a legend
  interrupts its fieldset's border by design, which breaks a card layout as soon
  as the question wraps to a second line.
- Every option carries an `aria-label` with the full scale point, so a screen
  reader announces "Strongly disagree" rather than an unlabelled control.
- Results move focus to the result heading and are announced in place; progress
  is reported through an `aria-live` region.
- The navigation stacks and scrolls horizontally below 52rem instead of
  collapsing behind a hamburger, so every destination stays reachable with no
  JavaScript. The header also stops being sticky there, which keeps a two-row
  bar from eating a short viewport.
- Visible focus rings throughout, a skip link, and `prefers-reduced-motion`
  honoured for all transitions and smooth scrolling.

## Configuration

The production origin comes from `PUBLIC_SITE_URL`, defaulting to
`https://xenapsis.com`. Set it once and canonicals, `og:url`, JSON-LD `@id`s,
the sitemap and `robots.txt` all follow:

```bash
PUBLIC_SITE_URL=https://staging.example.com npm run build
```

## Content notes

Comparison pages compare *categories* of test — gated vs ungated, free vs paid —
rather than making factual claims about specific named competitors, since those
claims could not be verified at build time and would age badly.

The guides state where the evidence does not support common industry claims,
including that type-based instruments do not reliably predict job performance.
That is a deliberate trust position, not an oversight.

## Deploying

`npm run build` emits a static `dist/` deployable to any static host. The build
fails on any SEO regression, so a broken deploy will not reach production
silently.
